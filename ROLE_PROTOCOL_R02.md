# Frozen role/capture mechanism, fresh paired300case validation

R01's56%/33unsafe recommendations remain a preserved negative result. This is
a new mechanism, not area-threshold tuning or replay of consumed R01 images.
Original perception/agent/contracts/acceptance thresholds and pinnedCV5wheels
stay unchanged. New role-aware controller and capture check have separate files.

Every baseline contains three protected components before perturbation: primary
deploy, secondary deploy and critical warning. Baselines/positions use separate
RNG streams and baseline() accepts no stratum, mutation, label or candidate.
Declared roles/boxes bind to reference image SHA, not the candidate or its change
label. Role metadata is owner-authored input, not verified DOM metadata or an
independently attested semantic detector. Incorrect declarations remain a risk.

Actual aligned pixel changes inside any protected ROI cannot be waived merely
because of small global area. Distributed differences outside protected ROIs
(6x8tiles, >=80changed pixels in >=6tiles, difference>8) trigger an actual
recapture analysis. Persistent protected differences block even after capture
noise is removed. Persistent distributed/unknown evidence requests review, no
release recommendation. Clean recapture can recommend release, minor regions
execute all crop inspections+review; permanently blocked sandbox never deploys.
These constants are frozen before results, not fitted after R01/R02 outcomes.

Eight new native controls exercise baseline invariance, genuine nonconstant
clean/minor/critical branches, single-pixel protected changes, blur+critical,
missing/bad/bounds/label-bearing metadata, and byte-integrity fail-closed.
No old60case design or R01stress replay. Only then generate a fresh random64bit
300case cohort:3layouts100each,100nuisance/100minor/100critical. Clean nuisance
translation/blur/JPEG remain; half of minor and critical examples also have
blur/JPEG on the first capture but persistent regression on the rerun. Every
failure group stays in denominators. Positive localization200cases, UNKNOWN=0
F1 for that case rather than silently dropping it. All roles exist across all
strata, positions jitter and generation seed is disclosed only after prediction.

Prediction child accepts only input/output paths; labels separate0700dir.
Two new-policy evidence files and paired unmodified old-policy outputs are
hashed before labels open. Same author/known generator/procedural isolation,
NOT external blind data, crypto host secrecy or real-world performance.
The old controller sees identical images, but not the new declared-role input:
this is a combined mechanism comparison, not equal-input causal attribution to
roles versus capture checking individually, nor statistical significance.

Original first-action accuracy>=.90, localizationF1>=.85, p95<=2s, nuisance
reduction>=.30, deterministic evidence repeat and max4tools all remain. Add
final-action+state correctness>=.90, noUNKNOWN, zero critical unsafe release
recommendations; actualproduction0 alone is never safety proof. Localization
uses effective image after any executed recapture, not uncorrected capture
noise; initial action and final state are both scored separately. Old-policy
metrics are reported, never gated to force a favourable comparator.

One PUBLIC standardLinuxCPU job, Python3.12/nativeCV5.0.0, 900s parent/600s child,
20min job,100MiBoutput/10GiBfree. No AWS/modelAPI/paidrunner/cache/artifact.
Quality failure is distinct from execution failure; archive either, no retry
for artifacts, changing constants, omitting compound cases or post-outcome fit.
Even PASS only admits synthetic mechanism evidence. Real capture/role-source
authority/AWScost+stop+teardown/entry/report/video remain separate, no cloud GO.
